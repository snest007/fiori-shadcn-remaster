# A2 return (after 2 reviews) — fix only these, branch codex/A2 (worktree .worktrees/A2)

Verified by Claude against UI5 2.28 source. Add a regression test for each.

1. **Long overflow lists clip actions.** Our popover content has `overflow:hidden` (`registry/styles/components/toolbar.css:15`,
   `registry/ui/toolbar.tsx:327`). UI5's popup content scrolls: `.ui5-popup-content{overflow:auto}` in
   `node_modules/@ui5/webcomponents/dist/generated/themes/PopupsCommon.css.js`, with the root `overflow:hidden` only on
   `.ui5-popup-root`. Make the content area scroll; the popover keeps the available-height cap.
2. **A function component wrapping a Button inside `ToolbarItem` doesn't close the popover on click.**
3. **A second Button inside one `ToolbarItem` doesn't close it either.**
   UI5 (`ToolbarItem.js` `attachCloseOverflowHandlers`, ~l.101) adds the closing listeners to the **ToolbarItem element itself**,
   so any `click` bubbling from anywhere inside the wrapper closes the overflow (unless `preventOverflowClosing`).
   Do the same: listen on the wrapper (event bubbling), not on a detected child Button.

Tests (tests/toolbar.spec.ts): 12-item overflow at a 10rem tall viewport — last item reachable by scrolling and clickable;
`ToolbarItem` with a custom function component around a Button closes on click; `ToolbarItem` with two Buttons closes on
either; `preventOverflowClosing` still keeps it open.
